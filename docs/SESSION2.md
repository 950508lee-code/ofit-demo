# 세션 2 과제① 업무 바통(인수인계) 출품 설계 (2026-10-26)

사용자 판정: **세션 2 지정과제 ① 업무 바통으로 출품한다.** 오핏의 구조(업무분장 → 반복업무 → 처리 순서 → 기록)는 그대로 두고, 그 위에 "AI가 근거 있는 인수인계 초안을 만들고 전임자가 검토·확정하는" 기능을 얹는다.

> **2026-10-26 사용자 판정: AI 모델 연결 개발은 보류.** 먼저 오핏에 쌓인 데이터만으로(AI 없이) 인수인계 초안이 어디까지 되는지 확인하고, 부족한 것이 입력 구조로 풀리는지 본다. AI는 제품의 정체성이 아니라, 필요성이 입증됐을 때 쓰는 선택 도구다. 아래 4·5절의 AI 부분은 보류 상태의 설계 기록이다.

한 줄: **기존 도구가 인수인계 때 문서를 모은다면, 오핏은 평상시에 쌓인 업무·일정·처리 순서·기록을 인수인계의 원료로 쓴다. AI는 정리되지 않은 자료만 맡는다.**

## 1. 대회 요구와 대응 (붙임1 7~10쪽)

| 과제 기본 기능 | 오핏 |
|---|---|
| 한글·PDF·엑셀 등 섞인 자료를 폴더째 넣어도 작동 | 인수인계 흐름에 '자료 넣기'(폴더 선택). HWPX·PDF·XLSX·CSV·TXT·DOCX. 구형 HWP는 "HWPX로 저장해 넣어 주세요" 안내 |
| 자료에 근거한 인수인계 초안, 내용별 출처 확인 | 초안의 모든 줄에 출처(오핏 기록 또는 파일·쪽·문단). 인용이 원문에 실제로 있는지 프로그램이 대조 |
| 전임자가 결과를 검토·수정 | 검토 화면: 항목마다 원문 나란히, 받아들이기 / 고치기 / 빼기 → 확정분만 인수인계에 실림 |
| (선택) 시기별 할 일 → 연간 달력 | 반복업무에서 계산 + 자료에서 찾은 일정. 오핏 달력에 표시 |
| (선택) R&R·연락망·현안 정리, 공식 문서와 개인 메모 구분, 누락·충돌·불확실 표시 | 협의할 사람, 진행 중인 현안 칸. 출처 종류(공식 문서 / 메모 / 오핏 기록) 표시. 대조 실패는 '확인 필요' |
| (선택) 후임자 질문에 자료 근거로 답변 | 여유가 되면. 답에 출처 필수 |
| 공통 규칙: 모델 비종속(2종 이상), 민감자료 금지, 원본 읽기 전용 | 모델 주소만 바꾸는 연결층, 젬마·엑사원 등 2종 구동 입증. 모의 자료만(`mock/`). 원본은 읽기만, 산출물은 오핏 상태에 따로 |

평가: 활용성 40 · 완성도 30 · 확산 용이성 30(모델 비종속, 정보화사업 이관 용이성).

## 2. 초안의 출처별 분담

| 초안 칸 | 만드는 방법 | 출처 표시 |
|---|---|---|
| 시기별 할 일 | 반복업무 일정에서 계산(**AI 없음**) + 자료에서 AI가 찾은 일정 | 업무 기준표 / 파일·쪽 |
| 협의할 사람·부서 | 주고받은 요청 기록(**AI 없음**) + 자료에서 AI가 찾은 사람 | 요청 n건 / 파일·문단 |
| 진행 중인 현안 | 끝나지 않은 요청·일정(**AI 없음**) + 완료 메모·자료 요약(AI) | 기록 날짜·사람 / 파일 |
| 처리 순서·주의 | 이미 적힌 처리 순서(**AI 없음**). 비어 있으면 자료에서 AI가 제안 | 오핏 처리 순서 / 파일·쪽 |
| 남길 말 | 전임자가 직접(기존 인수인계 '남길 말') | 전임자 |

AI 없이 만드는 칸이 먼저 채워지고, AI 칸은 "제안"으로 구분해 보인다.

## 3. 처리 흐름

```
자료 넣기(폴더) ─ 글자 뽑기(브라우저 안, 외부 요청 없음) ─ 조각 나누기(파일·쪽·문단 위치 유지)
                                                         │
오핏 상태(업무·반복업무·처리 순서·기록·요청) ─ 규칙 초안 ───┤
                                                         ▼
                                       AI 초안(조각만 넘김, JSON으로 받음)
                                                         ▼
                                  인용 대조(원문에 있는지) → 통과 / 확인 필요
                                                         ▼
                                  전임자 검토(받아들이기·고치기·빼기)
                                                         ▼
                        확정 → 인수인계(기존 흐름)에 실림 → 후임자 수락 → 업무·처리 순서·메모로 들어감
```

## 4. 모듈 (새 파일)

| 파일 | 하는 일 |
|---|---|
| `src/extract/` | 형식별 글자 뽑기. HWPX(zip 안 `Contents/section*.xml`의 `hp:t`), PDF(pdf.js, 쪽 번호 유지), XLSX(시트·행), DOCX(`word/document.xml`), TXT·CSV. 결과 = `{file, kind, loc: '3쪽' | '2문단' | 'B5', text}[]` |
| `src/llm.ts` | 모델 연결층. OpenAI 호환 `/v1/chat/completions` 하나로 묶는다(Ollama·vLLM·공통기반 모두 이 방식 제공). 설정: 주소, 모델 이름, 키(선택). 내 정보 > 'AI 연결' 화면. 외부 주소는 막지 않지만 기본값은 `http://localhost:11434/v1`(PC 안 Ollama) |
| `src/draft.ts` | 규칙 초안(오핏 상태에서) + AI 초안 요청·검증 |
| `src/views/HandoverDraft.tsx` | 검토 화면 |

새 npm 의존성: `pdfjs-dist`(PDF), `jszip`(HWPX·DOCX·XLSX zip). 엑셀은 jszip으로 `xl/sharedStrings.xml`·`sheet*.xml`을 직접 읽어 의존성을 줄인다. 모두 번들에 들어가 외부 요청 0건 원칙을 지킨다.

## 5. AI 요청과 검증 규칙

- 넘기는 것: 업무 이름, 이미 아는 반복업무 목록(중복 제안 방지), 자료 조각들(`[id] 파일 · 위치 · 글`).
- 받는 것(JSON만):
  ```json
  {"items": [{"kind": "schedule|contact|issue|step|caution",
              "text": "후임자에게 보일 한 줄",
              "when": "매월 25일 | 2026-11-첫째 주 | 없음",
              "quote": "근거 원문을 그대로 옮긴 짧은 구절",
              "chunk": "조각 id"}]}
  ```
- 지시: 자료에 없는 내용은 쓰지 않는다. 모든 항목에 `quote`와 `chunk`가 있어야 한다. 모르면 비운다.
- **검증(프로그램):** `quote`가 그 조각 원문에 공백을 무시하고 들어 있으면 '근거 확인', 아니면 '확인 필요'(빨간 점, 기본 선택 해제). `quote`·`chunk`가 없는 항목은 버린다.
- `when`은 오핏 해석기(`takeRule`)로 다시 읽어 반복 규칙이면 반복업무 제안으로, 날짜면 일정으로 보낸다.
- 모델 응답이 JSON이 아니면 한 번 다시 묻고, 그래도 아니면 "AI 초안을 만들지 못했어요. 규칙 초안만 보여 드려요."

## 6. 검토 화면 (전임자)

- 왼쪽: 초안 칸별 항목(시기별 할 일 / 협의할 사람 / 진행 중인 현안 / 처리 순서·주의). 항목마다 출처 칩(오핏 기록 · 파일명 쪽), 근거 확인 / 확인 필요.
- 오른쪽: 고른 항목의 원문 조각, 인용 부분 강조.
- 항목 동작: 받아들이기(기본 선택) · 고치기(글 수정) · 빼기.
- 아래: "확정하고 인수인계에 담기" → 기존 인수인계 흐름(받을 사람 → 넘길 업무 → … → 미리보기)으로.
- 후임자 수락 시: 확정 일정은 일정/반복업무 제안(업무 표준 제안으로 올라감, 기존 승인 구조), 처리 순서·주의는 그 반복업무의 처리 순서로, 현안·협의할 사람은 인수인계 '남길 말' 아래 별도 칸으로.

## 7. 시연 흐름 (5분 영상)

1. 김건강(예산·회계 담당) 홈: 평상시 쓰던 할 일과 처리 순서.
2. 발령 → 인수인계 하기 → **자료 넣기**: `mock/전임자자료_김건강/` 폴더.
3. 초안: AI 없이 채워진 칸(반복업무 일정, 요청 기록) + AI 제안 칸(메모·지침·일정표·메일에서). 출처 눌러 원문 확인. '확인 필요' 하나 고치기.
4. 확정 → 박공단에게 인수인계.
5. 박공단 수락 → 홈에 받은 업무, 오늘 할 일, 처리 순서와 주의, 협의할 사람.
6. 설정에서 모델을 바꿔(젬마 → 엑사원) 같은 초안이 나오는 것 보여 주기.

## 10. 실험 A: 새 입력칸 없이 기존 기능만으로 (2026-10-26)

김건강(예산·회계)에 화면에서 할 수 있는 행동만 했다(저장 함수 그대로 호출). 초안은 `src/draft/rule.ts`(AI 없음).

| 구분 | 내용 |
|---|---|
| 기존 데이터에서 자동으로 | 반복업무 4(25일 지출결의, 5일 법인카드, 분기 첫 달 10일 집행률, 매일 전표 결재), 지출결의 처리 순서 4단계, 지난 기록(완료 메모) 3 |
| 기존 기능에 추가 입력한 뒤 | 연 1회 일정 3(3월 집행계획 재확인, 11월 관서운영경비, 12/15 이월 보고), 한 번 있는 현안 1(11/2 공사 대금 2차분), 주의 2(분할 결의, 법인카드 이중 지급) |
| 여전히 못 얻은 것 | 협의할 사람 3(정회계·이광진·최표준), 현안의 사정("준공검사 조서가 아직 안 옴") |
| 추가 입력에 든 행동 | 일정 등록 창에서 반복 '매 1년' 3번, 빠른 입력 1줄, 순서 고치기에서 '주의 넣기' 1번, 비어 있던 법인카드 순서 1줄 + 주의 1줄 |

발견한 기존 기능의 문제(새 입력칸과 별개):
- **빠른 입력이 '매년'을 못 읽는다.** "매년 3월 31일 연간 집행계획 재확인"을 넣으면 '매년'이 제목에 남고 2027-03-31 한 번짜리가 된다. 사용자는 잘못 들어간 줄 모를 수 있다. 업무 표준의 한 줄 입력(`parseDuty`)도 같은 해석기라 연 1회 반복업무를 업무 표준으로 올릴 수 없다.
- **연 1회 일정이 업무가 아니라 개인 할 일로 들어간다.** 인수인계 때 전임자가 직접 골라 넘겨야 하고, 인수인계 없이 업무를 고른 사람에게는 오지 않는다. 업무 표준에 들어가야 할 정보다.
- **할 일에 사정을 적을 곳이 없다.** 현안의 맥락은 인수인계 '남길 말'에만 쓸 수 있다.

## 11. P0·P1 확인 (2026-10-26)

사용자 판정: 데이터 보완 실험은 중단. 평가 기준은 정답표 일치율이 아니라 **후임자가 따로 다시 입력하지 않고 이어받을 수 있는가**.

확인 방법: 저장 함수(`store.ts`)·해석기(`parse.ts`)·날짜 계산(`days.ts`)을 node로 직접 실행. 화면(React)은 이 환경에서 빌드할 수 없어(npm 차단) 띄워 보지 않았다.

### P0-1 '매년' 해석 — 고침
`takeRule`에 `매년 N월 N일`을 더했다. 빠른 입력과 업무 표준 한 줄 입력이 같은 함수를 쓰므로 둘 다 고쳐졌다.

| 입력 | 빠른 입력 | 업무 표준 |
|---|---|---|
| 매년 3월 31일 연간 집행계획 재확인 | 연간 집행계획 재확인 · 매년 3월 31일 | 같음 |
| 연간 집행계획 재확인 매년 3월 31일 | 같음(순서 무관) | 같음 |
| 3월 31일 연간 집행계획 재확인 | 한 번(2027-03-31), 바뀌지 않음 | 주기 없음 |
| 매월·분기·매주·셋째 주·매일 | 이전과 같음 | 이전과 같음 |

남은 한계: '매년 2월 말일'은 못 읽는다(연 반복 규칙의 날짜가 숫자만 받음). '매년 2월 30일'은 받아들이고 달력에는 2월 마지막 날로 들어간다.

### P0-2 업무 표준 연 1회 반복업무의 승계 — 됨
김건강이 예산·회계 업무 표준에 연 1회 3건 제안 → 경영지원 분류 관리자(한경영) 승인 → 반복업무 7개.

| 후임자 | 받은 것 |
|---|---|
| 박공단(인수인계 수락) | 업무 반복업무 7개 전부, 2027-03-31 연간 집행계획 재확인이 달력에 들어감. 개인 할 일은 김건강이 고른 1건(공사 대금)만 |
| 이광진(인수인계 없이 업무만 고름) | 업무 반복업무 7개 전부. 개인 할 일은 없음 |
| 김건강(넘긴 뒤) | 예산·회계 회차 사라짐. 넘기지 않은 개인 할 일(매주 금요일 개인 정리)은 남음 |

개인 할 일과 업무 반복업무는 섞이지 않는다. 기존 화면도 둘을 이미 나눈다.
- 업무 반복업무: 업무(자리) 화면 → 업무 표준 → 반복업무 더하기.
- 개인 할 일: 빠른 입력, 일정 등록 창 '나'.
- 인수인계: 업무는 '넘길 업무', 개인 할 일은 '그 밖의 일정'에서 따로 고른다.

남은 문제(새 화면 없이 생기는 문제): 빠른 입력에 '매년 …'을 쓰면 개인 할 일로 들어간다. 업무에 속하는 일인지는 사용자가 알아서 업무 표준으로 가야 한다.

### P1 후임자 시나리오 (김건강 예산·회계 → 박공단)

| 단계 | 판정 | 근거 |
|---|---|---|
| 업무분장 선택 | 구현 | 가입·자리 잡기에서 업무 고르기(`signup`·`takeUnits`), 받을 인수인계 수락(`acceptHandover`) |
| 오늘·이번 주 반복 일정 | 구현 | 수락한 날부터 회차가 들어감(`itemsInRange`). 이번 주에는 부서 요청 1건, 11월 지출결의·법인카드·관서운영경비, 12월 이월 보고 |
| 처리방법·주의 | 구현(주의는 `claude/writing-guide` 브랜치, 합치기 전) | 처리 순서는 업무에 붙어 있어 그대로 보임(지출결의 4단계). 비어 있던 순서는 비어 있음 |
| 진행 중 현안 | 일부 | 다른 부서가 업무 담당자에게 보낸 요청은 자동으로 후임자에게 감. 전임자의 개인 현안은 인수인계에서 골라야 감. 사정(“조서가 아직 안 옴”)은 '남길 말'에만 |
| 참고자료 | 미구현 | 반복업무의 '근거' 한 줄, 처리 순서의 '서식' 이름만. 파일·링크 연결 없음 |

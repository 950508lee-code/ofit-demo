# OFIT 조작 체계 — 같은 행동은 같은 이름 · 같은 모양 · 같은 자리 (2026-10-26, 확정 전)

> 사용자 판정(2026-10-26): 화면마다 문구를 따로 고치니 같은 문제가 되풀이된다('반복업무 더하기 제안'이 또 나옴). 시연 자료·화면 채우기는 멈추고, **OFIT 전체에서 같은 행동이 같은 이름·모양·위치로 나타나도록** 조작 체계를 먼저 통일한다. 글자를 아이콘으로 바꾸지 않는다.
> 근거 자료: `docs/ACTIONS.md`(단추 162개 분류 · 중복 표현).

## 1. 이름 — 닫힌 낱말 목록

| 낱말 | 뜻 | 쓰는 곳 |
|---|---|---|
| **추가** | 새 항목을 만든다 | 반복업무 · 자료 · 단계 · 주의 · 업무 · 부서 · 빠른 입력 |
| **편집** | 있는 내용을 고친다 | 업무 개요 · 업무 안내 · 처리방법 · 내가 만든 할 일 · 일정 |
| **삭제** | 있는 항목을 없앤다 | 단계 · 자료 · 내가 만든 할 일 |
| **저장** | 편집·추가한 것을 반영한다 | 편집 칸 · 일정 등록 창(나에게) |
| **취소** | 입력을 그만둔다(아무것도 바뀌지 않음) | 편집 칸 · 창 · 흐름 |
| **보기** | 다른 곳으로 가서 본다 | '○○에서 보기', 기록 보기 |
| 완료 · 완료 취소 | 할 일을 끝냄 / 끝낸 것을 무름 | 할 일 상세 · 받은 요청 |
| 보내기 | 다른 사람에게 넘긴다 | 요청 · 인수인계 · 일정 등록 창(부서에) · 업무 표준 변경 요청 |
| 받기 · 거절 | 넘어온 것을 받거나 돌려보냄 | 인수인계 |
| 승인 · 반려 | 관리자가 업무 표준 변경을 받아들이거나 돌려보냄 | 관리자 검토 |
| 확인 | 읽었음을 알림 | 받은 업무 카드 |
| 다음 · 이전 | 흐름의 단계 넘김 | 가입 · 자리 잡기 · 기관 등록 |
| 닫기 | 판을 닫는다 | 오른쪽 판 머리 |
| 일정 등록 | 일정 등록 창 열기(확정 낱말) | 왼쪽 위 하나 |
| 되돌리기 | 방금 한 일을 무름 | 알림 띄움 안에서만 |

- **대상은 헷갈릴 때만 앞에:** 자료 추가 · 단계 추가 · 주기 변경 · 인수인계 취소. 그 밖의 말(하기·제안·올리기·쓰기·붙이기·고치기·더하기·넣기·만들기·떼기·빼기·지우기·그만두기)은 단추에 쓰지 않는다.
- **'제안'은 단추 이름이 아니다.** 승인 절차를 설명하는 문장에서만 쓴다(변경 화면 안).
- **단추에는 행동만.** 숫자·상태·설명을 섞지 않는다('보내기 · 업무 2개' → 단추 '보내기', 2개는 위 줄).

## 2. 모양 — 네 가지

| 모양 | 역할 | 생김 | 한 판에 |
|---|---|---|---|
| **주요 단추** | 그 화면을 끝내는 행동(완료 · 저장 · 보내기 · 받기 · 승인 · 다음 · 일정 등록) | 채운 단추, 높이 44 | **하나** |
| **보조 단추** | 그 자리에서 하는 행동(편집 · 추가 · 취소 · 거절 · 반려 · 닫기) | 테두리 단추, 보이는 높이 36 · 누르는 영역 44(KRDS) | 묶음마다 하나 |
| **이동 글자** | 다른 곳으로 가기(○○에서 보기 · 기록 보기 · 업무 이름) | 진한 글자 + 밑줄, 단추 테두리 없음 | 제한 없음 |
| **관리 목록** | 드물고 영향이 큰 행동(주기 변경 · 반복업무 삭제 · 변경 기록 · 복원 · 인수인계 취소 · 반복 중지 · 업무 변경 · 부서 이동) | 머리 오른쪽 보조 단추 **'관리'** → 아래로 펼친 글자 목록. 삭제처럼 되돌리기 어려운 것은 목록 맨 아래 선 뒤 | 화면(판)마다 하나 |

- 같은 모양은 같은 역할만. 이동을 테두리 단추로, 편집을 밑줄 글자로 만들지 않는다.
- **'+ 추가':** 추가만 앞에 '+'를 붙인다(글자 단추 안의 기호이지 아이콘 대체가 아님 — 판정 필요, 4장).

## 3. 자리

| 자리 | 놓는 것 | 예 |
|---|---|---|
| **화면 머리 오른쪽** | 이동 글자 하나 + 관리 | 업무 문서: '내 업무에서 보기' · 관리 |
| **묶음 제목 오른쪽** | 그 묶음의 보조 단추 **하나** | 반복업무 '+ 추가' · 처리방법 '편집' · 참고자료 '+ 추가' · 업무 안내 '편집' |
| **줄 오른쪽** | 상태·날짜만(행동 없음) | 반복업무 줄: '10월 30일(금)' |
| **편집 칸 아래 오른쪽** | [취소] [저장] — 저장이 주요 | 처리방법 편집, 업무 안내 편집 |
| **판 아래** | 왼쪽 메모 칸, 오른쪽 끝 주요 단추 | 할 일 상세: [한 줄 남기기] [완료] |
| **판 머리 오른쪽** | 닫기(+ 관리) | 할 일 상세 · 알림 판 |
| **흐름 아래** | [이전] … [다음] | 가입 · 자리 잡기 |
| **변경 화면(업무 표준) 안** | 지금 값 → 바꿀 값 → 한 줄 "관리자가 승인하기 전까지 일정은 그대로입니다" → [취소] [보내기] | 주기 변경 · 반복업무 추가 |

- 줄 안에는 단추를 두지 않는다(편집 중에만 단계·자료 줄 오른쪽에 '삭제').
- 문서 본문 사이에 단추를 끼우지 않는다(묶음 제목 오른쪽으로).

## 4. 문장

- 단추 이름에 절차를 쓰지 않는다. **절차는 누른 다음 화면에서 한 줄.** 주기 변경·반복업무 추가 화면에는 반드시 "관리자가 승인하기 전까지 일정은 그대로입니다"(사용자: 승인 전에는 일정이 바뀌지 않음을 분명히).
- 작성 요령은 **빈 칸일 때만** 한 줄. 이미 쓴 문서에는 보이지 않는다.
- 결과 안내는 화면에 늘 두지 않고 알림 띄움 한 번("저장했습니다").
- 관리 정보(고친 날·고친 사람·변경 기록)는 본문과 떨어뜨려 문서 맨 아래 한 줄 또는 관리 목록 안.
- **한 화면에 같은 정보는 한 번**(`docs/ACTIONS.md` 5장).
- 보조 글자: 15px 이상, 대비 4.5:1 이상. 더 진하게(7:1 넘게)는 실제 화면에서 위계가 무너지지 않는지 본 뒤에 정한다(사용자).

## 5. 판정이 필요한 것
1. 판 닫기: '닫기' 글자(추천) / ✕ — 앞서 ✕를 승인했으나 '아이콘 바꾸기 금지'와 부딪힘.
2. '+ 추가'의 '+': 글자 단추 안 기호로 둘지, '추가'만 둘지.
3. 관리 단추 이름: '관리'(추천) / '설정' / '더 보기'.

## 6. 업무 문서(색인) 판정(2026-10-26 사용자) — 이 체계로 다시 그릴 때 따를 것
- 채택: 반복업무가 본문 첫 칸, 이름·주기(다음 예정일은 8장 판정으로 뺌), 업무 안내 별도 칸, 개요 번호 없음.
- 조건부: 매일·매주·매월·분기 묶음은 업무 수가 적을 때 빈 구획이 생기지 않게(예: 한 묶음에 하나뿐이면 묶음 머리 생략 등), 오른쪽 참고자료·근거는 좁은 화면에서도 닿게.
- **보류: 처리방법 첫 단계 미리 보기** — 반복업무가 20개면 목록이 길어진다. 기본은 "월간 복무 점검 / 매월 말일 · 다음 10월 30일"까지. 미리 보기 있음·없음 두 방식을 비교해 정한다.
- **삭제: "더하기·주기 바꾸기는 확인을 거쳐 … · 반복업무 더하기 제안" 문장.** 반복업무 묶음 제목 옆 '+ 추가'만. 주기 변경은 반복업무 문서(관리)에서.
- 목차·오른쪽 참고자료 배치는 실제 화면을 본 뒤 결정. 시각적 완성도는 승인하지 않음.
- 시연 자료 더 넣기: 보류.

## 7. 판정(2026-10-26 사용자) — 부분 승인
- **닫기 = ✕ 채택**(나안). '글자를 무조건 아이콘으로 바꾸지 않는다' ≠ '아이콘을 쓰지 않는다'. 닫기는 ✕만으로 대부분 안다.
  - 모달·팝업·상세 판 **오른쪽 위 ✕**, 마우스를 올리면 '닫기' 툴팁, 화면 읽기 프로그램에는 '닫기'.
  - 편집 중 저장하지 않은 내용이 있으면 닫기 전에 확인. 편집·입력을 그만두는 것은 **취소**.
  - 일반 페이지에서 이전 화면으로 돌아가는 것은 ✕가 아니다(뒤로 가기·탐색의 영역).
- 용어 통일(1장): **승인.** ✕ 예외: **승인.**
- 모든 화면에 주요 단추 하나: **철회.** 모든 관리 행동을 오른쪽 위 메뉴에 모으기: **철회.**
- **새 기준:** ① 행동의 의미(추가·편집·삭제·저장…) ② 맥락(목록·문서·편집 화면·설정 화면) ③ 시각적 강조(주요·보조·위험)를 **따로** 판단한다. 같은 '추가'도 화면에 따라 주요일 수도 보조일 수도 있다. 층을 고정된 자리·모양과 일대일로 묶지 않는다.
- **기능은 사용자가 찾을 거라 예상하는 자리에:**

| 행동 | 자리 |
|---|---|
| 반복업무 추가 | 반복업무 목록의 추가 단추 |
| 주기 변경 · 반복 중지 | 반복업무 문서의 **반복 설정** 영역 |
| 업무 추가 | 업무 목록의 추가 단추 |
| 변경 기록 | 문서의 이력 링크 |
| 복원 | 이전 판 화면 안에서 |
| 삭제 · 부서 이동 | 관리 메뉴 가능 |

- '관리' 단추 이름은 정하지 않는다. 먼저 **관리 메뉴가 실제로 필요한 화면을 골라낸다**(편집·추가·이력을 제자리에 두고 나면 필요 없는 화면이 있을 것).

## 8. 반복업무 목록 세 방식 비교(2026-10-26 시안, 판정 전)
- 조건: 지어낸 반복업무 13개(긴 이름 포함), 맡은 사람·맡지 않은 사람, PC 760 · 폰 390. 머리 '반복업무 13' + '+ 추가'. 오늘=10월 26일(월).
- 날짜 칸: 맡은 사람만. 오늘이면 굵게 '오늘', 7일 안은 진하게, 그 뒤는 회색. 맡지 않은 사람은 날짜 칸 없음.
- **A 주기별 영역:** 묶음 머리(매일 1 · 매주 2 …) 아래 줄. 높이 PC 979 · 폰 1135.
- **B 한 목록 + 주기 배지(다음 일정 순):** 이름 · [매월] 말일 · 날짜. 높이 PC 776 · 폰 1036.
- **C 주기 영역 + 간결한 행:** 왼쪽 칸에 묶음 첫 줄에만 주기. 높이 PC 702 · 폰 880.
- 3초 훑기(설계자 추정, 사용자 시험 아님): B는 '가장 가까운 일'이 맨 위라 맡은 사람에게 가장 빠르다. A·C는 '매월 일이 무엇무엇인가'에 빠르고, 날짜 순서는 눈이 여러 묶음을 오가야 한다. 맡지 않은 사람은 날짜가 없어 B의 정렬 이점이 사라진다.
- **판정(2026-10-26 사용자): 다음 일정 순 정렬 불필요, 다음 예정일도 뺀다.** 까닭: '다음에 뭘 하나'는 오늘·달력·내 업무가 답한다(업무지식=구조), 날짜 순은 순서가 날마다 바뀌어 문서 자리를 기억할 수 없다, 맡음/안 맡음에 따라 다른 문서가 된다. 그래서 업무 문서의 반복업무 목록은 **주기 묶음 고정 순서**(매일·매주·매월·분기·매년), 줄은 **이름 · 주기 상세만**, 누가 보든 같다. B안은 장점이 사라져 제외. **최종: C안**(사용자) — 왼쪽 칸에 주기를 묶음 첫 줄에만, 묶음 사이 가는 선, 간결한 줄(이름 굵게 · 주기 상세 회색), 묶음 개수는 보이지 않음. 폰은 왼쪽 칸 유지·이름과 주기 상세는 두 줄.

## 9. 관리 메뉴 없이 풀기 — 화면별 점검(2026-10-26, 판정 전)
> 사용자 지시: 목적은 '관리 메뉴가 필요한 화면 찾기'가 아니라 **관리 메뉴 없이 풀 수 있는 행동을 최대한 떼어 내기**. '관리'라는 공통 메뉴를 꼭 만든다는 전제를 버린다. 기본 자리: 추가=목록 제목 옆 · 편집=내용 옆 · 삭제=편집 화면 안 · 변경 기록=문서 아래 · 복원=이전 판 화면 · 주기 변경·반복 중지=반복 설정 · 부서 이동=별도 설정.

### 9-1. 읽는 상태와 편집 상태
- **읽는 상태:** 행동은 **묶음 제목 옆에 하나씩만**('편집' 또는 '+ 추가'), 테두리 없는 조용한 글자 단추. 줄 안에는 단추 없음(줄을 누르면 그 문서·상세로).
- **편집 상태:** 편집을 누른 **그 묶음만** 바뀐다. 줄마다 '삭제', 단계 사이 '단계 추가', 고른 단계에 '주의 추가', 아래 [취소] [저장]. 편집 중에는 다른 묶음의 '편집'을 숨긴다(한 번에 하나).
- 삭제는 읽는 상태에 나오지 않는다. 늘 편집 상태 안에서만.

### 9-2. PC와 폰
- **호버는 기능을 숨기는 데 쓰지 않는다.** PC 호버는 줄 바탕색(누를 수 있음 신호)만. 마우스를 올려야만 보이는 단추는 없다 → 폰에서 따로 찾을 것이 없다.
- 폰에서 길게 누르기·밀어서 지우기는 쓰지 않는다(발견이 안 되고 실수가 잦음).
- 폰 편집은 **그 묶음만 담은 전체 화면**: 위 왼쪽 '취소', 위 오른쪽 '저장'(자판에 가리지 않게). PC는 읽던 자리에서 바로.
- 폰 오른쪽 판(할 일 상세·알림)은 아래에서 올라오는 전체 화면, 오른쪽 위 ✕. 주요 단추(완료)는 화면 아래에 붙인다(엄지 자리).

### 9-3. 화면별 네 가지

## 10. 확정 원칙과 구현(2026-10-26 사용자 조건부 확정 → 구현)
> **OFIT의 조작은 대상과 가까운 곳에 배치하고, 현재 상황에 필요한 행동만 보여준다.** 읽기와 편집을 명확히 구분하며, 편집 중에만 세부 조작을 노출한다. 반복업무의 운영 변경은 별도 설정에서 처리하고, 업무지식은 누구나 직접 수정할 수 있도록 한다. 삭제보다 기록 보존을 우선하며, PC와 모바일 모두에서 숨겨진 조작 없이 기능을 발견할 수 있어야 한다. 공통 관리 메뉴는 두지 않는다.

- 9장에서 고친 것(사용자): '묶음마다 단추 하나'는 원칙이 아니다 — 기준은 **불필요한 행동을 노출하지 않는 것**(참고자료는 '+ 추가'와 '편집' 둘). 폰 편집은 **복잡도에 따라**: 긴 처리 순서·업무 안내는 전체 화면, 참고자료 하나·반복업무 한 줄 추가는 그 자리.
- 반복 중지 / 삭제 / 완료 구분: 반복 중지 = 앞으로 반복 일정이 생기지 않음 · 삭제 = 업무 정의와 관련 자료 자체를 없앰 · 완료 = 특정 회차를 끝냄. **일반 사용자에게 반복업무 삭제는 두지 않는다.**
- 구현한 것(코드): 낱말 통일(편집·삭제·저장·취소·추가·인수인계·업무 변경·부서 이동·반복 중지 등), 단추 안 숫자·설명을 단추 밖 한 줄로, 받기·확인·저장은 채운 단추, 판 닫기 ✕(적은 한 줄이 있으면 닫기 전 확인), 업무지식 반복업무 목록 C안(본문 첫 칸 · '+ 추가' · 검토 중 줄 · 줄을 누르면 그 처리 순서로), 처리 순서 편집(단계 '삭제' · '+ 단계 추가' · '주의 추가'는 고른 단계에만), 참고자료 '+ 추가'(새로 적기/등록된 자료) · '편집'(줄마다 삭제 → 저장), 업무 안내 '편집' · 마지막 편집은 맨 아래 한 줄, 내가 만든 할 일 삭제는 편집 창 안, 부서 이동·분류별 관리자는 내 정보, 업무 변경은 맡은 업무 목록 끝, 검토할 것이 없으면 검토 칸을 두지 않음, 폰 긴 편집은 전체 화면(위 왼쪽 취소 · 위 오른쪽 저장).
- (2026-10-26 이어서) **반복업무 문서 구현:** 업무 문서(색인)의 반복업무 줄을 누르면 반복업무 문서. 처리방법은 반복업무 문서에만 있고 색인에는 없다(복제하지 않음). 할 일 상세는 같은 원본(StepsBlock)에서 단계만 체크칸으로 가져오고 편집 단추·출처 줄은 두지 않으며, 참고자료는 읽기만(있을 때만), '업무지식에서 보기'는 그 반복업무 문서로. 찾기 결과(반복업무 이름·처리 순서 문장)도 반복업무 문서로. 실제 앱에서 따라가 확인: 색인 → 문서 → 관리자가 단계 추가 → 담당자 할 일 상세에 그대로 → 상세에서 문서로 → 담당자가 우리 부서 방식 저장 → 할 일 상세에 반영 → 찾기로 문서 이동(모두 같은 원본).
- 아직 하지 않은 것: 업무지식 편집 권한 넓히기(조직 구성원 누구나 — 정의는 확정, 구현 승인 범위 밖), 이전 판 열람·복원·비교, 반복업무 문서(반복업무마다 자기 문서), 부서별 업무 안내·운영 방식 정리.

## 11. 반복 중지 명세안(2026-10-26, 구현 전 · 판정 필요)
**지금 코드의 사실:** 반복업무의 회차는 저장해 두지 않고 주기 규칙에서 그때그때 계산한다(오늘·달력·알림·윈도우 알림 모두). 그래서 '이미 만들어진 미래 회차'는 반복업무에는 없다. 미리 만들어 두는 것은 반복 **요청**(두 달치)뿐이고, 이미 '반복 중지'가 있다(손대지 않은 앞으로의 회차는 삭제, 누가 손댄 회차는 남김).

| 항목 | 제안 |
|---|---|
| 무엇이 바뀌나 | 반복업무에 '중지일' 하나를 둔다. 중지일부터는 회차를 계산하지 않는다 → 오늘·달력·알림·윈도우 알림에서 저절로 빠진다(남아서 알림을 보내는 회차가 생길 수 없음). |
| 중지일 | 승인한 날의 **다음 날**(처음 값). 변경 화면에서 날짜를 고를 수 있다. 오늘 회차는 남는다. |
| 미리 체크해 둔 처리 순서(앞날 회차의 진행 표시) | 지우지 않고 두되 보이지 않는다. 다시 시작하면 그대로 보인다. |
| 과거 | 완료 기록·한 줄 기록·처리 순서·참고자료·업무 안내는 모두 그대로. |
| 업무지식 문서 | 반복업무 목록에 그대로 남고 회색 '중지 · 11월 2일부터'. 눌러서 처리 순서·기록을 읽을 수 있다. |
| 승인 | 반복업무는 모두 업무 표준(같은 업무를 맡은 모두에게 들어감)이므로 **늘 관리자 확인**(주기 변경과 같은 절차). 관리자 본인이면 바로. 승인 전까지 일정은 그대로라고 변경 화면에 한 줄. |
| 알림 | 승인되면 그 업무를 맡은 모두에게 '○○ 반복업무가 11월 2일부터 중지됩니다' 한 번. |
| 다시 시작 | 같은 반복 설정 칸에서 '다시 시작'(같은 승인 절차). 중지 기간의 회차는 되살리지 않는다. |
| 반복 요청 | 지금처럼 보낸 사람이 바로 중지(승인 없음). 이미 만든 앞으로의 회차 중 아무도 손대지 않은 것은 삭제, 받은 사람이 완료·회신한 회차는 남김. |
| 내가 만든 반복 할 일 | 나만의 일이라 승인 없음. 편집 창 안 '삭제'(지금 구현). 중지가 필요하면 같은 방식으로 나중에. |

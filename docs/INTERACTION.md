# OFIT 조작 체계 — 같은 행동은 같은 이름 · 같은 모양 · 같은 자리 (2026-10-26, 확정 전)

> 사용자 판정(2026-10-26): 화면마다 문구를 따로 고치니 같은 문제가 되풀이된다('반복업무 더하기 제안'이 또 나옴). 시연 자료·화면 채우기는 멈추고, **OFIT 전체에서 같은 행동이 같은 이름·모양·위치로 나타나도록** 조작 체계를 먼저 통일한다. 글자를 아이콘으로 바꾸지 않는다.
> 근거 자료: `docs/ACTIONS.md`(단추 162개 분류 · 중복 표현).

## 1. 이름 — 닫힌 낱말 목록

| 낱말 | 뜻 | 쓰는 곳 |
|---|---|---|
| **추가** | 새 항목을 만든다 | 반복업무 · 자료 · 단계 · 주의 · 업무 · 부서 · 빠른 입력 |
| **편집** | 있는 내용을 고친다 | 업무 개요 · 업무 안내 · 처리방법 · 내가 만든 할 일 · 일정 |
| **삭제** | 있는 항목을 없앤다 | 단계 · 자료 · 내가 만든 할 일 |
| **저장** | 편집·추가한 것을 반영한다 | 편집 칸 · 일정 등록 창(나에게) |
| **취소** | 입력을 그만둔다(아무것도 바뀌지 않음) | 편집 칸 · 창 · 흐름 |
| **보기** | 다른 곳으로 가서 본다 | '○○에서 보기', 기록 보기 |
| 완료 · 완료 취소 | 할 일을 끝냄 / 끝낸 것을 무름 | 할 일 상세 · 받은 요청 |
| 보내기 | 다른 사람에게 넘긴다 | 요청 · 인수인계 · 일정 등록 창(부서에) · 업무 표준 변경 요청 |
| 받기 · 거절 | 넘어온 것을 받거나 돌려보냄 | 인수인계 |
| 승인 · 반려 | 관리자가 업무 표준 변경을 받아들이거나 돌려보냄 | 관리자 검토 |
| 확인 | 읽었음을 알림 | 받은 업무 카드 |
| 다음 · 이전 | 흐름의 단계 넘김 | 가입 · 자리 잡기 · 기관 등록 |
| 닫기 | 판을 닫는다 | 오른쪽 판 머리 |
| 일정 등록 | 일정 등록 창 열기(확정 낱말) | 왼쪽 위 하나 |
| 되돌리기 | 방금 한 일을 무름 | 알림 띄움 안에서만 |

- **대상은 헷갈릴 때만 앞에:** 자료 추가 · 단계 추가 · 주기 변경 · 인수인계 취소. 그 밖의 말(하기·제안·올리기·쓰기·붙이기·고치기·더하기·넣기·만들기·떼기·빼기·지우기·그만두기)은 단추에 쓰지 않는다.
- **'제안'은 단추 이름이 아니다.** 승인 절차를 설명하는 문장에서만 쓴다(변경 화면 안).
- **단추에는 행동만.** 숫자·상태·설명을 섞지 않는다('보내기 · 업무 2개' → 단추 '보내기', 2개는 위 줄).

## 2. 모양 — 네 가지

| 모양 | 역할 | 생김 | 한 판에 |
|---|---|---|---|
| **주요 단추** | 그 화면을 끝내는 행동(완료 · 저장 · 보내기 · 받기 · 승인 · 다음 · 일정 등록) | 채운 단추, 높이 44 | **하나** |
| **보조 단추** | 그 자리에서 하는 행동(편집 · 추가 · 취소 · 거절 · 반려 · 닫기) | 테두리 단추, 보이는 높이 36 · 누르는 영역 44(KRDS) | 묶음마다 하나 |
| **이동 글자** | 다른 곳으로 가기(○○에서 보기 · 기록 보기 · 업무 이름) | 진한 글자 + 밑줄, 단추 테두리 없음 | 제한 없음 |
| **관리 목록** | 드물고 영향이 큰 행동(주기 변경 · 반복업무 삭제 · 변경 기록 · 복원 · 인수인계 취소 · 반복 중지 · 업무 변경 · 부서 이동) | 머리 오른쪽 보조 단추 **'관리'** → 아래로 펼친 글자 목록. 삭제처럼 되돌리기 어려운 것은 목록 맨 아래 선 뒤 | 화면(판)마다 하나 |

- 같은 모양은 같은 역할만. 이동을 테두리 단추로, 편집을 밑줄 글자로 만들지 않는다.
- **'+ 추가':** 추가만 앞에 '+'를 붙인다(글자 단추 안의 기호이지 아이콘 대체가 아님 — 판정 필요, 4장).

## 3. 자리

| 자리 | 놓는 것 | 예 |
|---|---|---|
| **화면 머리 오른쪽** | 이동 글자 하나 + 관리 | 업무 문서: '내 업무에서 보기' · 관리 |
| **묶음 제목 오른쪽** | 그 묶음의 보조 단추 **하나** | 반복업무 '+ 추가' · 처리방법 '편집' · 참고자료 '+ 추가' · 업무 안내 '편집' |
| **줄 오른쪽** | 상태·날짜만(행동 없음) | 반복업무 줄: '10월 30일(금)' |
| **편집 칸 아래 오른쪽** | [취소] [저장] — 저장이 주요 | 처리방법 편집, 업무 안내 편집 |
| **판 아래** | 왼쪽 메모 칸, 오른쪽 끝 주요 단추 | 할 일 상세: [한 줄 남기기] [완료] |
| **판 머리 오른쪽** | 닫기(+ 관리) | 할 일 상세 · 알림 판 |
| **흐름 아래** | [이전] … [다음] | 가입 · 자리 잡기 |
| **변경 화면(업무 표준) 안** | 지금 값 → 바꿀 값 → 한 줄 "관리자가 승인하기 전까지 일정은 그대로입니다" → [취소] [보내기] | 주기 변경 · 반복업무 추가 |

- 줄 안에는 단추를 두지 않는다(편집 중에만 단계·자료 줄 오른쪽에 '삭제').
- 문서 본문 사이에 단추를 끼우지 않는다(묶음 제목 오른쪽으로).

## 4. 문장

- 단추 이름에 절차를 쓰지 않는다. **절차는 누른 다음 화면에서 한 줄.** 주기 변경·반복업무 추가 화면에는 반드시 "관리자가 승인하기 전까지 일정은 그대로입니다"(사용자: 승인 전에는 일정이 바뀌지 않음을 분명히).
- 작성 요령은 **빈 칸일 때만** 한 줄. 이미 쓴 문서에는 보이지 않는다.
- 결과 안내는 화면에 늘 두지 않고 알림 띄움 한 번("저장했습니다").
- 관리 정보(고친 날·고친 사람·변경 기록)는 본문과 떨어뜨려 문서 맨 아래 한 줄 또는 관리 목록 안.
- **한 화면에 같은 정보는 한 번**(`docs/ACTIONS.md` 5장).
- 보조 글자: 15px 이상, 대비 4.5:1 이상. 더 진하게(7:1 넘게)는 실제 화면에서 위계가 무너지지 않는지 본 뒤에 정한다(사용자).

## 5. 판정이 필요한 것
1. 판 닫기: '닫기' 글자(추천) / ✕ — 앞서 ✕를 승인했으나 '아이콘 바꾸기 금지'와 부딪힘.
2. '+ 추가'의 '+': 글자 단추 안 기호로 둘지, '추가'만 둘지.
3. 관리 단추 이름: '관리'(추천) / '설정' / '더 보기'.

## 6. 업무 문서(색인) 판정(2026-10-26 사용자) — 이 체계로 다시 그릴 때 따를 것
- 채택: 반복업무가 본문 첫 칸, 이름·주기·다음 예정일, 업무 안내 별도 칸, 개요 번호 없음.
- 조건부: 매일·매주·매월·분기 묶음은 업무 수가 적을 때 빈 구획이 생기지 않게(예: 한 묶음에 하나뿐이면 묶음 머리 생략 등), 오른쪽 참고자료·근거는 좁은 화면에서도 닿게.
- **보류: 처리방법 첫 단계 미리 보기** — 반복업무가 20개면 목록이 길어진다. 기본은 "월간 복무 점검 / 매월 말일 · 다음 10월 30일"까지. 미리 보기 있음·없음 두 방식을 비교해 정한다.
- **삭제: "더하기·주기 바꾸기는 확인을 거쳐 … · 반복업무 더하기 제안" 문장.** 반복업무 묶음 제목 옆 '+ 추가'만. 주기 변경은 반복업무 문서(관리)에서.
- 목차·오른쪽 참고자료 배치는 실제 화면을 본 뒤 결정. 시각적 완성도는 승인하지 않음.
- 시연 자료 더 넣기: 보류.

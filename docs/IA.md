# 정보 노출 구조 점검 — 무엇을 보이고, 접고, 따로 떼고, 그 자리에서 끝내나 (2026-10-26, 점검 · 코드 수정 전)

> 사용자 판정(2026-10-26): 다음 UI 과제는 단추가 아니라 **화면의 깊이와 정보 노출 방식**.
> 원칙: **핵심 정보는 바로 보여주고, 부가 정보는 접고, 독립적인 지식은 별도 문서로 분리하며, 짧은 행동은 현재 화면에서 끝낸다.**
> 이 문서는 지금 앱(`claude/session2`)을 그대로 따라가며 본 것이다. 클릭 수는 작업자가 센 값이고 사용자 시험이 아니다.

## 1. 네 가지 방식 (사용자 기준)

| 방식 | 언제 | OFIT |
|---|---|---|
| 별도 페이지 | 독립적으로 읽거나 오래 머무는 정보 | 업무 문서(색인), 반복업무 문서, 변경 기록(비교·복원) |
| 아코디언 | 지금 맥락에서 일부만 펼쳐 확인 | 짧은 부가 정보(지난 수행 기록, 반복 설정 등) |
| 사이드 패널 | 지금 화면을 유지하며 확인·실행 | 할 일 상세, 알림 판, 지난 기록 보기 |
| 모달 | 짧은 입력·중요한 결정 | 일정 등록, 반복업무 추가, 주기 변경, 반복 중지 확인 |

**아코디언 다섯 원칙:** ① 핵심 정보(처리방법)는 접지 않는다 ② 독립 문서를 아코디언에 넣지 않는다(색인에서 처리방법을 펼치지 않음) ③ 짧고 보조적인 정보에만 ④ 접힌다는 것이 보여야 한다 — 제목 옆 펼침 표시(▸/▾) + 화면 읽기 프로그램에 펼침 상태 ⑤ 한 화면에 접힌 영역이 5~6개를 넘으면 화면을 나눌지 다시 본다.
- 펼침 표시(▸/▾)는 '장식 화살표 금지'의 예외로 기록한다(✕와 같은 기능 표시, 글자 대신이 아니라 글자 옆).

## 2. 화면별 점검

'늘 보임' = 핵심(사용자가 반드시 봐야 함) · '접음' = 필요할 때만 · '따로' = 별도 페이지·패널·모달.

| 화면 | 지금 | 늘 보임 | 접음 | 따로 | 걸리는 것 |
|---|---|---|---|---|---|
| **오늘** | 인사말 · 알림 한 줄 · 이번 주 · 고른 날 할 일 · 빠른 입력 · (있으면) 받을 인수인계·받은 업무 판 | 그대로 | 없음 | 할 일 → 패널, 일정 등록 → 모달 | 없음. 이미 '그 자리에서 끝내는' 화면 |
| **달력** | 달 칸 + 고른 날 목록 | 그대로 | 없음 | 할 일 → 패널 | 없음 |
| **할 일 상세(패널)** | 이름·날짜 · 처리방법(체크) · 관련 근거 · 참고자료(업무 전체) · **지난번**(인수인계 말 + 3건) · 한 줄 남기기 · 완료 · 업무지식에서 보기 | 이름·기한 · 처리 단계 · 필요한 참고자료 · 완료 · 반복업무 문서로 | **지난번 — 판정 필요(4장 ①)** | 변경 기록·반복 설정은 두지 않음(지금도 없음) | 참고자료가 업무 전체 자료(④ 반복업무별 연결에서 해결) |

| **반복업무 문서** | 이름·주기·다음 · 처리방법(+ 변경 기록이 **그 자리에서** 펼쳐지고 판 보기·복원까지) · 참고자료 · 지난번 · 반복 설정 | 이름·주기·다음 · 처리방법 · 참고자료 | 지난 수행 기록 · 반복 설정 (2개) | **변경 기록 → 별도 페이지**(판 목록 → 판 보기·비교 → 복원), 주기 변경·반복 중지 → 모달 | 지금은 비교·복원이 문서 한가운데서 펼쳐져 처리방법을 밀어낸다 |

## 3. 세 사람으로 따라가기 (지금 → 제안)

### 신규 담당자 — 처음 맡은 '월간 복무 점검'의 처리방법을 찾는다
| | 지금 | 제안 |
|---|---|---|
| 오늘에 회차가 있을 때 | 줄 누름 → 패널에 처리방법: **1** | 같음: **1** |
| 회차가 없을 때 | 업무지식 → (인사·복무) → 반복업무 줄: **2~3** | 같음 |
| 업무 전체를 처음부터 배우기 | 반복업무마다 색인으로 돌아갔다 다시 들어감(13개면 26번 이동) | 반복업무 문서 아래 **'이전 · 다음 반복업무'**(같은 업무 안, 이동 글자 둘): 13개를 한 방향으로 읽음 — 아코디언 없이 색인과 문서의 역할을 지킨다 |
| 걸리는 것 | 처리방법은 이미 늘 보임(접지 않음) | — |

### 기존 담당자 — 금요일 할 일을 끝낸다
| | 지금 | 제안 |

| 매일 하는 일 | 줄 → 체크칸: **1 + n** | 같음 |

### 인수인계 받은 사람 — 업무 전체와 쌓인 지식을 파악한다
| | 지금 | 제안 |
|---|---|---|

## 4. 판정할 것 (→ 6장에서 모두 판정됨)
1. **할 일 상세의 '지난번'**: 사용자가 정한 패널 항목(이름·기한 · 처리 단계 · 참고자료 · 완료 · 문서로)에 없다. 그러나 전임자가 남긴 말("5일이 토요일이라 4일 처리")은 처음 맡은 사람이 그 회차를 할 때 가장 쓸모 있다. (가) 패널에서 빼고 반복업무 문서의 '지난 수행 기록'에서만 (나) 패널 맨 아래 접어 둠(1클릭) (다) 전임자가 인수인계로 남긴 말만 늘 보이고 나머지 기록은 뺌.
2. 내 업무에서 펼친 업무 안의 '지난 기록 5건'·'달마다 몰리는 때'를 빼고 패널(지난 기록 보기)·업무 문서로 보낼지 — '지난 기록은 내 업무가 주인'이라는 앞선 판정과 부딪힌다.
3. 반복업무 문서 '이전 · 다음 반복업무' 이동을 둘지.
4. 반복업무 추가를 지금의 그 자리 칸에서 모달로 바꿀지(사용자 제안표는 모달. 앞선 판정 "짧은 편집은 그 자리"와 견줌 — 추가는 업무 표준 변경 요청이라 모달이 맞아 보임).

## 5. 바꾸지 않는 것
- 오늘·달력·알림 판·흐름·내 정보의 깊이.
- 처리방법은 어디서도 접지 않는다.
- 색인에서 처리방법을 펼치지 않는다(색인은 찾는 곳, 반복업무 문서는 읽는 곳).

## 6. 판정(2026-10-26 사용자) · 최종 원칙 · 구현

**최종 평가 기준 — 아코디언의 개수가 아니라 세 가지.** 접힌 칸이 2개여도 매번 펼쳐야 하면 나쁜 UI이고, 5개여도 각각 독립적인 참고 정보면 괜찮다.
- **발견성:** 필요한 정보가 어디 있는지 알 수 있는가?
- **접근성:** 자주 쓰는 정보를 불필요하게 펼치지 않아도 되는가?
- **맥락 유지:** 정보를 확인한 뒤 원래 하던 일을 계속할 수 있는가?

> OFIT의 UI는 정보를 최대한 숨기는 방향이 아니라, **불필요한 정보만 뒤로 보내는 방향**으로 설계한다. 업무를 수행하는 사람에게 지금 필요한 정보가 가장 먼저 보이게.

| 항목 | 판정 | 구현 |
|---|---|---|
| 할 일 상세의 지난번 | 다안 취지 채택, '인수인계 메모만'은 반대 | **'지난 처리 메모' 1건을 접지 않고 바로**: 이 반복업무의 수행 기록 중 메모가 있는 가장 최근 것(빈 메모 제외) + 인수인계하며 남긴 말도 후보, 가장 최근 하나. 없으면 칸 없음. 전체 기록은 반복업무 문서 '지난 수행 기록'. AI 중요도 평가·메모 작성 강요 없음. 반복되는 주의사항은 사람이 공통 처리방법으로 옮긴다(메모는 일시적 맥락, 처리방법은 축적된 지식) |
| 내 업무의 지난 기록 | 조건부 승인 | 펼친 업무 = 반복업무(다음 날짜) + 받은 요청. 달마다 몰리는 때는 뺌. 지난 기록은 없애지 않고 '지난 기록 n'(오른쪽 판으로)·업무 문서에서, 인수인계는 그 업무 아래 그대로 |
| 이전 · 다음 반복업무 | 승인 | 반복업무 문서 아래, 색인과 같은 순서(주기 묶음), 가운데 'n / 전체'(폰에서도) |
| 반복업무 추가 | 승인(모달) | 업무 문서·내 업무의 '+ 추가' → 창. 관리자 확인 절차는 보내기 바로 위 한 줄 |
| 반복업무 문서 부가 정보 | 사용자 처음 제안대로 | 처리방법·참고자료는 늘 보임, 지난 수행 기록·반복 설정은 접음, **변경 기록은 같은 자리의 별도 화면**(판 목록 → 판 보기·비교 → 복원, 위 이동 글자로 문서로 돌아옴) |
| 업무 문서(색인) | 사용자 처음 제안대로 | 반복업무 · 업무 안내 · 참고자료는 늘 보임, 지난 기록 · 이 자리에 있었던 사람 · 반복업무 변경 기록은 접음(제목은 늘 보임) |
- 접는 칸 모양(`Fold`): 제목 줄 전체가 단추(48px), 앞에 ▸/▾, `aria-expanded`. 펼침 표시는 '장식 화살표 금지'의 예외(기능 표시).
- 아직 보지 않은 것: 접은 칸들이 실제로 매번 펼쳐지는지(접근성) — 설계를 모르는 직원 시험(`docs/USERTEST.md`)에서 확인할 항목으로 남긴다.

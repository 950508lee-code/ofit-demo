# 공동 편집 · 변경 이력 설계 — 반복업무 문서 다음 단계 (2026-10-26, 설계 · 구현은 단계별)

> 사용자 우선순위(2026-10-26): ① 반복업무별 독립 문서(구현함) ② 누구나 업무지식 편집 ③ 변경 이력·비교·복원 ④ 부서별 업무 안내 정리. ①~③은 함께 설계하고 단계별로 구현한다. 원본은 하나(반복업무 문서), 할 일 상세는 필요한 부분만 가져온다.
> 검증 방식: 시안을 여러 장 만들지 않고 실제 앱에서 업무 문서 → 반복업무 문서 → 처리방법 편집 → 할 일 상세가 하나의 정보로 이어지는지 본다.

## 1. 지금 코드의 사실
- 처리방법: 공통 처리 순서(총괄·분류 관리자만 편집, `stepHistory`에 편집마다 전·후가 남음) + 단계 아래 '○○지사 운영 방식'(그 업무 담당자, 그 부서에만).
- 업무 안내: 부서마다 하나, 그 부서 담당자만 편집, **이력 없음**(마지막 편집자·날짜만).
- 참고자료: 업무에 붙음(반복업무와 연결 없음), 맡은 사람만 추가·삭제, 이력 없음.

## 2. 단계 ② 누구나 편집 — 하나의 처리방법
- 반복업무 문서의 처리방법 '편집'을 조직 구성원 누구에게나(맡지 않은 사람 포함). 저장하면 바로 반영(승인 없음), 일정은 바뀌지 않음.
- 저장할 때 단계를 지우면 "n단계가 삭제됩니다"를 한 번 묻는다(중요한 내용 삭제 확인).
- 참고자료 추가·삭제도 누구나(정의에 따라 '맡은 사람만'을 바꿈 — 이미 사용자 판정).
- **부딪히는 것:** '○○지사 운영 방식'(부서별 층)은 '하나의 업무, 하나의 표준'과 어긋난다(부서별 철회 판정). 누구나 공통을 고칠 수 있게 되면 부서 방식을 따로 쓸 까닭이 줄어든다 → 판정 필요(아래 4장).

## 3. 단계 ③ 변경 이력 · 비교 · 복원
- 판(版) = 저장할 때마다 남는 전체 내용. 처리방법은 지금 `stepHistory`(전·후)를 그대로 판으로 쓴다(새로 저장 모양을 만들지 않음). 업무 안내는 판을 새로 남긴다(저장 모양이 바뀌므로 `VER` 올리고 `migrate`, 자료는 지우지 않음).
- 문서 맨 아래 '변경 기록 n' → 판 목록(날짜 · 편집한 사람 · 뺀 것/새로 쓴 것 요약).
- 판을 열면 그 판의 내용과 지금과의 차이(뺀 줄·새로 쓴 줄을 글자로 표시, 색만으로 구분하지 않음). 그 화면 안에만 '이 판으로 복원'.
- 복원은 지우기가 아니라 **새 편집 하나**로 남는다(복원한 것도 이력에 남고, 되돌릴 수 있음).

## 4. 판정(2026-10-26 사용자): 가안 + 기존 부서별 기록 보존
| 구분 | 결정 |
|---|---|
| 부서별 운영 방식 신규 작성 | 중단 |
| 기존 부서별 기록 | 읽기 전용으로 보존 · 삭제 금지 |
| 공통 처리방법 | 모든 구성원이 직접 편집 |
| 기존 기록의 공통 문서 반영 | 필요한 내용만 사람이 골라 반영(**자동으로 합치지 않음** — 지사 관행이 다르거나 공식 기준과 부딪힐 수 있음. 옮길 때 중복은 정리하고 적용 조건을 함께 적는다) |
| 정리 완료 후 | 기존 기록은 이력으로 조회 |
- 공동 편집의 세 가지: ① 즉시 반영 ② 변경 이력 자동 보존(누가·언제·무엇, 이전 내용과 비교) ③ 복원(복원도 새 이력). **②·③ 없이 공동 편집만 먼저 내지 않는다** — 같이 구현.
- 공식 지침과 직원이 쓴 처리방법은 시각적으로 구분(공동 편집한 내용이 공식 기준처럼 보이면 안 됨).
- 다음 순서: ① 신규 작성 중단 ② 누구나 편집 ③ 이력·비교·복원(②와 함께) ④ 반복업무별 참고자료 연결 ⑤ 기존 부서별 기록 정리.
- **참고자료(④, 다음 작업):** 업무 공통자료는 업무 문서(색인)에서, 반복업무 관련 자료는 그 반복업무 문서에서, 할 일 상세는 그 반복업무의 관련 자료만. 파일을 복제하지 않고 기존 자료에 연결만 더한다(공통자료 중 필요한 것을 연결해 재사용).

## 5. 구현(2026-10-26) — ①②③
- 편집 권한: 같은 조직 구성원 누구나(`canEditCommon`). 저장하면 바로 반영 · 알림 띄움에 '되돌리기'. 줄이 줄어들면 "n개 줄을 삭제합니다 … 이전 판에 남습니다" 확인.
- 부서 운영 방식: 쓰기 화면·저장 함수를 뺐다(`saveDeptWays` 삭제). 이미 쓴 것은 단계 아래 '○○지사 운영 방식 · 이전 기록'으로 읽기만, 지우지 않는다.
- 판: 저장 모양은 바꾸지 않고 기존 `stepHistory`(편집마다 전·후 전체)를 판으로 쓴다(`StepChange.restored`만 선택 칸으로 더함). 처음 판 = 첫 편집의 '전' = '처음 등록 자료'.
- 변경 기록: 처리방법 아래 '마지막 편집 날짜 · 사람 · 변경 기록 n' → 판 목록(새것부터, 지금 판 표시, 새로 쓴 줄·삭제한 줄 수, 복원이면 어느 판으로) → '보기' → 그 판의 내용(지금 없는 줄에 '지금은 없음' 글자 표시)과 '이 판 뒤에 새로 쓴 것' → '이 판으로 복원'(확인 창) → 새 판으로 남음.
- 공식과 구분: 처리방법 제목 아래 "직원이 함께 쓰는 처리방법입니다. 공식 기준이 아닙니다"(관련 근거가 있으면 "공식 기준은 아래 관련 근거를 따릅니다"). 관련 근거는 테두리 상자 + '관련 근거 · 공식 규정·지침' 이름표. 시연 자료에는 관련 근거가 아직 없다(시연 자료 추가는 보류).
- 맡은 사람 알림: 남이 처리방법을 편집·복원하면 '내 업무에서 바뀐 것'에 뜬다(내가 한 것은 빼고).
- 점검: `scripts/screens/coedit-flow.mjs`(9단계: 문서 → 담당자 편집 → 안 맡은 사람 삭제 → 알림 → 판 3개 → 판 보기 → 복원 → 할 일 상세).
- 아직: 업무 안내(부서마다)의 판·복원 — 업무 안내는 ⑤ 부서별 정리 때 함께. 판 비교는 줄 단위(같은 글이 있는지)로, 글자 단위 비교는 하지 않는다.

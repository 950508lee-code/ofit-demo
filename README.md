# 오핏(OFIT): 업무가 일의 주인이 되는 업무관리체계

[공공행정] 2026 공공 AI 대전환 챌린지 세션 2 지정과제① 업무 바통(인수인계) 출품작입니다.

## 어떤 문제를 푸나요

인사이동 때 쓰는 인수인계서에는 실제 일정, 협의 관계, 진행 상황 같은 업무 노하우가 충분히 담기지 않습니다. 자료는 개인 PC에 한글·엑셀·PDF·메일로 흩어져 있고, 후임자는 과거 문서를 다시 찾고 주변에 물어 가며 처음부터 업무를 익힙니다.

인수인계서가 부실한 까닭은 떠나는 날 한꺼번에 기억을 되살려 써야 하기 때문입니다. 오핏은 인수인계를 그날 쓰는 문서가 아니라, 평소 일하면서 저절로 쌓이는 기록으로 바꿉니다.

## 오핏의 방법

**일의 주인은 사람이 아니라 업무(자리)입니다.**

- 업무를 고르면 그 업무의 반복업무(매월 25일 지출결의 마감 같은 일)가 할 일과 달력에 저절로 들어옵니다.
- 처리 순서, 주의할 점, 참고자료, 완료할 때 남긴 한 줄 기록이 사람이 아니라 업무에 붙어 쌓입니다.
- 인수인계하면 업무와 그 기록이 통째로 넘어갑니다. 인수인계 없이 업무만 골라도 같은 반복업무와 기록을 받습니다.
- 다른 부서의 요청은 사람이 아니라 '그 부서의 그 업무 담당자'에게 갑니다. 담당자가 바뀌면 새 담당자에게 갑니다.

## 주요 기능

| 기능 | 내용 |
|---|---|
| 업무 고르기 | 가입할 때 부서와 맡을 업무를 고르면 반복업무가 바로 들어옵니다 |
| 홈 | 이번 주 날마다 할 일, 고른 날 할 일, 한 줄 빠른 입력("매주 금요일 3시 주간 회의", "매년 3월 31일 집행계획 재확인"을 알아듣습니다) |
| 업무 화면 | 처리 순서와 주의, 반복업무와 몰리는 달, 참고자료(파일 위치·링크), 받은 요청, 지난 기록, 이 자리를 거쳐 간 사람 |
| 처리 순서 쓰기 | 단계마다 적고, 실수하기 쉬운 곳은 그 단계 바로 아래 '주의' 줄로 남깁니다 |
| 인수인계 | 넘길 업무와 그 밖의 일정을 골라 보내고, 받는 사람이 수락하면 옮겨 갑니다. 넘긴 사람의 지난 기록은 남습니다 |
| 발령 | 맡던 업무 정리, 새 부서, 받을 인수인계, 새 업무 고르기를 한 흐름으로 합니다 |
| 요청 | 다른 부서의 업무 담당자에게 요청을 보내고, 완료 현황을 봅니다. 반복 요청도 됩니다 |
| 업무 표준 | 빠진 반복업무는 누구나 올리고, 분류 관리자나 총괄 관리자가 승인하면 같은 업무를 맡은 모두에게 들어갑니다 |
| 그룹 | 부서를 넘어 함께 하는 일을 체크리스트로 나눠 맡습니다 |
| 달력·알림 | 한 달 일정과 받은 알림을 한곳에서 봅니다 |

### 후임자가 따로 다시 입력하지 않고 이어받는 것

| 후임자에게 필요한 것 | 오핏에서 |
|---|---|
| 내가 맡은 업무 | 받은 인수인계나 업무 고르기로 정해집니다 |
| 오늘·이번 주에 할 일 | 맡은 날부터 반복업무 회차가 홈과 달력에 들어옵니다 |
| 어떻게 하는지, 주의할 점 | 전임자가 남긴 처리 순서와 주의가 업무 화면에 있습니다 |
| 진행 중인 일 | 업무 담당자 앞으로 온 요청은 새 담당자에게 옵니다. 전임자 개인 일정은 인수인계 때 골라 넘깁니다 |
| 참고자료 | 업무에 붙은 지침·서식·시스템 주소가 그대로 있습니다 |

## 실행 방법

Node.js 20.19 이상(또는 22.12 이상)이 필요합니다.

```
npm install
npm run dev        # http://localhost:5180
```

배포용으로 만들 때:

```
npm run build      # dist/ 폴더에 정적 파일이 생깁니다
```

- 서버가 없습니다. 모든 상태는 브라우저 저장소(localStorage)에 저장됩니다.
- 외부 요청이 없습니다. 글꼴(Pretendard)도 앱 안에 들어 있어 업무망(폐쇄망)에서도 그대로 뜹니다.
- 처음 상태로 돌리려면 로그인 화면의 "처음 상태로 되돌리기"를 누릅니다.

## 시연

- 시연 계정: 김건강(광진지사, 예산·회계 담당), 최표준(업무 표준 총괄 관리자), 한경영(경영지원 분류 관리자). 박공단, 이광진은 시연 중에 가입합니다.
- 사람 바꾸기: 왼쪽 아래 "시연용 계정 바꾸기"로 로그아웃 없이 바꿉니다.
- 시연 순서(약 5분): [`docs/DEMO.md`](docs/DEMO.md)

## 자료와 보안

- 저장소의 사람, 부서, 업무, 기록은 모두 시연용으로 지어낸 것입니다. 실제 기관의 업무 기준표, 조직표, 개인정보는 넣지 않았습니다.
- `mock/전임자자료_김건강/`은 인수인계 시연에 쓰는 지어낸 전임자 자료(업무 메모, 지침, 일정표, 메일 정리)입니다.
- 공공 GitLab 보안 검사(Gitleaks, Semgrep, OSV-Scanner, Trivy, Syft)를 통과했습니다.

## 폴더 구조

| 경로 | 내용 |
|---|---|
| `src/model.ts` | 데이터 모양과 시드 |
| `src/store.ts` | 모든 상태 변경(가입, 업무 맡기, 인수인계, 요청, 그룹, 업무 표준, 발령) |
| `src/schedule.ts` | 반복 규칙 계산, 공휴일 |
| `src/parse.ts` | 한 줄 입력 해석(날짜, 시간, 반복) |
| `src/views/` | 화면(홈, 업무 화면, 달력, 그룹, 일정 등록, 업무 표준 등) |
| `src/data/` | 시연용 업무 기준표와 부서 목록 |
| `src/extract/` | 한글(HWPX)·워드·엑셀·텍스트 파일에서 글자를 뽑는 모듈(화면 연결 전) |
| `src/draft/` | 오핏에 쌓인 기록으로 인수인계 초안 항목을 만드는 규칙(화면 연결 전) |
| `scripts/screens/` | 시연 흐름 자동 점검 스크립트 |
| `docs/` | 설계와 결정 기록 |

## 지금의 한계

- 서버가 없어서 여러 사람이 같은 데이터를 함께 보지 못합니다. 시연은 한 브라우저에서 사람을 바꿔 가며 합니다.
- 전임자의 업무 폴더를 넣어 초안을 만드는 화면은 아직 없습니다. 파일에서 글자를 뽑는 모듈과, 오핏 기록으로 초안 항목을 만드는 규칙만 있습니다.
- AI 모델 연결은 보류 중입니다. 먼저 오핏에 쌓인 기록만으로 인수인계가 어디까지 되는지 확인하고 있습니다. 연결할 때의 설계(특정 모델에 묶이지 않는 연결, 출처 대조, 전임자 검토)는 [`docs/SESSION2.md`](docs/SESSION2.md)에 있습니다.
- 실제 직원 대상 사용자 시험은 아직 하지 않았습니다.

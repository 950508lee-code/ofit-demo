# 오핏(OFIT)

[공공행정] 오핏(OFIT) — 반복 일정과 업무 노하우를 관리하고, 담당자가 바뀌어도 업무정보가 그대로 이어지는 웹서비스

2026 공공 AI 대전환 챌린지 세션 2 지정과제① 업무 바통(인수인계) 출품작입니다.

## 주요 기능

| 기능 | 내용 |
|---|---|
| 업무 고르기 | 가입할 때 부서와 맡을 업무를 고르면 반복업무가 바로 들어옵니다 |
| 오늘 | 이번 주 날마다 할 일, 고른 날 할 일, 한 줄 빠른 입력("매주 금요일 3시 주간 회의", "매년 3월 31일 집행계획 재확인"을 알아듣습니다) |
| 내 업무 | 맡은 업무마다 다음 할 일과 이번 달 끝낸 회차, 펼치면 반복업무·몰리는 달·받은 요청·지난 기록. 반복 할 일, 인수인계, 보낸 요청 |
| 업무지식 | 조직의 업무 전체를 왼쪽 목록에서 골라 읽습니다. 업무 안내(부서마다 쌓는 개요·예외·노하우), 처리 순서와 주의, 참고자료(파일 위치·링크), 거쳐 간 사람. 맡지 않은 업무도 읽습니다 |
| 업무 찾기 | 왼쪽 위 찾기 칸(`/` 키)에서 업무 이름, 업무 안내, 처리 순서를 한 번에 찾고, 그 문장을 보여 줍니다 |
| 처리 순서 쓰기 | 단계마다 적고, 실수하기 쉬운 곳은 그 단계 바로 아래 '주의' 줄로 남깁니다 |
| 인수인계 | 넘길 업무와 그 밖의 일정을 골라 보내고, 받는 사람이 수락하면 옮겨 갑니다. 넘긴 사람의 지난 기록은 남습니다 |
| 발령 | 맡던 업무 정리, 새 부서, 받을 인수인계, 새 업무 고르기를 한 흐름으로 합니다 |
| 요청 | 다른 부서의 업무 담당자에게 요청을 보내고, 완료 현황을 봅니다. 반복 요청도 됩니다 |
| 업무 표준 | 빠진 반복업무는 누구나 올리고, 분류 관리자나 총괄 관리자가 승인하면 같은 업무를 맡은 모두에게 들어갑니다 |
| 달력·알림 | 한 달 일정을 보고, 오른쪽 위 알림 종(안 읽은 숫자)에서 처리할 것과 받은 알림을 봅니다. 창이 열려 있으면 윈도우 알림도 띄웁니다 |

## 실행 방법 (설치·실행)

Node.js 20.19 이상(또는 22.12 이상)이 필요합니다.

```
npm install
npm run dev        # http://localhost:5180
```

배포용으로 만들 때:

```
npm run build      # dist/ 폴더에 정적 파일이 생깁니다
```

- 서버가 없습니다. 모든 상태는 브라우저 저장소(localStorage)에 저장됩니다.
- 외부 요청이 없습니다. 글꼴(Pretendard)도 앱 안에 들어 있어 업무망(폐쇄망)에서도 그대로 뜹니다.

## 작동 방법 (화면에서 써 보기)

시연 계정은 김건강(광진지사, 예산·회계 담당), 최표준(업무 표준 총괄 관리자), 한경영(경영지원 분류 관리자)입니다. 사람은 왼쪽 아래 "시연용 계정 바꾸기"로 로그아웃 없이 바꿉니다.

1. **시작:** 시연 주소를 열고 첫 화면에서 '여기서 시작'이 붙은 김건강을 누릅니다.
2. **오늘 할 일:** 오늘 화면 위쪽에 이번 주 날마다 할 일이, 아래에 고른 날 할 일이 보입니다. 할 일을 누르면 오른쪽에 처리 순서가 열리고, 한 줄 기록을 남기며 완료합니다.
3. **빠른 입력:** 아래 입력칸에 "매주 금요일 3시 주간 회의"처럼 쓰면 날짜·시간·반복을 알아듣고 할 일로 넣습니다.
4. **내 업무 · 업무지식:** 왼쪽 메뉴 '내 업무'에서 맡은 업무마다 다음 할 일과 이번 달 진행을 보고, 펼치면 반복업무와 지난 기록이 나옵니다. '업무지식'을 누르거나 할 일 줄의 업무 이름표(예: 예산·회계)를 누르면 그 업무의 업무 안내, 처리 순서, 참고자료를 문서로 읽습니다. 업무 안내는 그 자리에서 바로 고칩니다. 왼쪽 위 찾기 칸에서 낱말로 찾을 수도 있습니다.
5. **새 직원 가입:** 왼쪽 아래 이름을 눌러 내 정보 맨 아래 "로그아웃"을 누른 뒤 '새 직원으로 시작하기'로 이름, 조직, 부서(예: 광진지사)를 고릅니다. 맡을 업무를 고르면 반복업무가 바로 들어옵니다.
6. **인수인계:** 김건강으로 돌아가 내 업무의 '인수인계 하기'에서 받을 사람과 넘길 업무를 골라 보냅니다. 받는 사람으로 바꾸면 오늘 화면 맨 위에 받을 인수인계가 뜨고, 받으면 업무와 기록이 옮겨 갑니다.
7. **업무 표준:** 업무지식(또는 내 업무에서 업무를 펼친 곳)의 '반복업무 더하기'에 "매년 3월 31일 연간 집행계획 재확인"처럼 쓰고 올립니다. 한경영으로 바꿔 업무지식 맨 위 '업무 표준 검토'에서 승인하면, 그 업무를 맡은 모두에게 들어갑니다.
8. **처음 상태로:** 로그아웃한 뒤 로그인 화면의 "처음 상태로 되돌리기"를 누릅니다.

전체 시연 순서(약 5분)는 [`docs/DEMO.md`](docs/DEMO.md)에 있습니다.

## 1. 활용성

### 1-1. 행정업무 실정에 맞는다

**풀려는 문제.** 인사이동 때 쓰는 인수인계서에는 실제 일정, 협의 관계, 진행 상황 같은 업무 노하우가 충분히 담기지 않습니다. 자료는 개인 PC에 한글·엑셀·PDF·메일로 흩어져 있고, 후임자는 과거 문서를 다시 찾고 주변에 물어 가며 처음부터 업무를 익힙니다. 떠나는 날 한꺼번에 기억을 되살려 써야 하니 빠지는 것이 생깁니다.

**오핏의 방법: 일의 주인은 사람이 아니라 업무(자리)입니다.**

- 공공기관은 이미 업무분장으로 일한다는 점을 그대로 씁니다. 업무를 고르면 그 업무의 반복업무(매월 25일 지출결의 마감 같은 일)가 할 일과 달력에 들어옵니다.
- 처리 순서, 주의할 점, 참고자료, 완료할 때 남긴 한 줄 기록이 사람이 아니라 업무에 붙어 쌓입니다. 인수인계를 위한 입력을 따로 시키지 않습니다.
- **업무 표준은 공통으로, 실무 노하우는 현장에 축적합니다.** 반복 일정과 기본 처리 순서는 조직이 함께 쓰는 업무 표준이고, 부서마다 다른 예외와 노하우는 그 부서의 업무 안내에 남깁니다. 업무 안내는 쓰라고 시키지 않습니다.
- 인수인계하면 업무와 기록이 통째로 넘어갑니다. 인수인계 없이 업무만 골라도 같은 반복업무와 기록을 받습니다.
- 다른 부서의 요청은 사람이 아니라 '그 부서의 그 업무 담당자'에게 갑니다. 담당자가 바뀌면 새 담당자에게 갑니다.
- 반복 날짜는 공휴일과 주말을 따져 앞 근무일로 당깁니다.

**후임자가 따로 다시 입력하지 않고 이어받는 것**

| 후임자에게 필요한 것 | 오핏에서 |
|---|---|
| 내가 맡은 업무 | 받은 인수인계나 업무 고르기로 정해집니다 |
| 오늘·이번 주에 할 일 | 맡은 날부터 반복업무 회차가 홈과 달력에 들어옵니다 |
| 어떻게 하는지, 주의할 점 | 전임자가 남긴 처리 순서와 주의가 업무지식에 있습니다 |
| 이 부서만의 사정, 노하우 | 부서가 쌓아 온 업무 안내가 그대로 있습니다. 찾기 칸에서 '증빙'처럼 낱말로 찾습니다 |
| 진행 중인 일 | 업무 담당자 앞으로 온 요청은 새 담당자에게 옵니다. 전임자 개인 일정은 인수인계 때 골라 넘깁니다 |
| 참고자료 | 업무에 붙은 지침·서식·시스템 주소가 그대로 있습니다 |

**기대효과(정성).** 후임자가 첫날부터 할 일과 처리 순서를 보고 일을 시작합니다. 전임자는 인수인계서를 처음부터 쓰지 않고, 쌓인 것을 확인하고 남길 말만 더합니다. 부서 사이 요청이 담당자 교체 때 끊기지 않습니다. 실제 직원 대상 효과 측정은 아직 하지 않았습니다.

### 1-2. 전 기관이 함께 쓰고, 기관마다 맞춰 쓴다

| 기관마다 다른 것 | 오핏에서 맞추는 방법 |
|---|---|
| 업무와 반복업무 | 첫 화면 '우리 기관 등록하기'에서 업무 기준표를 올립니다. 열은 직렬, 단위업무, 반복업무, 주기 네 칸이고 엑셀을 CSV로 저장하면 됩니다(빈 양식 받기 제공) |
| 부서 구조 | 가입할 때 조직표에서 부서를 고르고, 없으면 그 자리에서 만듭니다 |
| 업무 표준 관리 | 총괄 관리자가 분류(직렬)마다 분류 관리자를 정합니다. 빠진 반복업무는 누구나 올리고 관리자가 승인합니다 |
| 주기 표현 | 매일, 매주 요일, 매월 날짜·말일, 매월 n째 주 요일, 분기, 매년을 한 줄 글로 씁니다 |

특정 기관 전용 기능은 넣지 않았습니다. 시연용 기준표(`src/data/demo.ts`)도 어느 기관이나 있는 경영지원·대민서비스·정보보안 업무로 만들었습니다.

### 2-2. 안정적 구동

- TypeScript strict로 작성했습니다(`npx tsc --noEmit -p .`).
- 시연 흐름 자동 점검 스크립트가 가입부터 알림까지 28단계를 헤드리스 크롬으로 돌리며 단계마다 기대 결과를 확인합니다. 앱 날짜를 고정해 요일과 상관없이 같은 결과가 나옵니다(`scripts/screens/`). 발령, 발령 중 같은 업무 주고받기도 따로 점검합니다.
- 외부 서버와 외부 요청이 없어 네트워크 상태에 따라 멈추지 않습니다.

### 2-3. 사용 편의성

- 정부 디자인 시스템(KRDS) 기준을 따릅니다. 누르는 곳은 44px 이상, 보조 글자 대비는 4.5:1 이상입니다.
- PC(1440px) 화면이 기준이고, 폰 화면도 맞춰 씁니다.
- 한 줄로 쓰면 날짜·시간·반복을 알아듣고, 쓰는 동안 어떻게 알아들었는지 보여 줍니다.
- 버튼 문구와 안내는 쉬운 한국어로 썼습니다.

## 3. 확산 용이성

### 3-1. 특정 모델에 묶이지 않는다

- 지금 제출한 핵심 기능(업무 배정, 일정 계산, 입력 해석, 인수인계)은 AI 모델 없이 규칙으로 동작합니다. 모델이 없는 기관, 모델을 바꾸는 기관에서도 그대로 씁니다.
- AI는 정리되지 않은 전임자 자료를 읽을 때만 쓰도록 설계했습니다. 연결은 OpenAI 호환 방식(`/v1/chat/completions`) 하나로 묶어, 기관 안의 모델(예: Ollama, vLLM, 공통 기반 모델) 주소와 모델 이름만 바꾸게 했습니다. 모델이 내놓은 항목은 인용이 원문에 실제로 있는지 프로그램이 대조하고, 전임자가 확인한 것만 넘깁니다.
- 이 AI 연결은 아직 구현하지 않고 보류 중입니다. 먼저 오핏에 쌓인 기록만으로 인수인계가 어디까지 되는지 확인하고 있습니다. 설계는 [`docs/SESSION2.md`](docs/SESSION2.md)에 있습니다.

### 3-2. 다른 기관과 정보화사업으로 옮기기 쉽다

| 항목 | 내용 |
|---|---|
| 구성 | Vite + React + TypeScript 정적 웹. `npm run build` 결과물(`dist/`)을 웹 서버에 올리면 됩니다 |
| 의존성 | 실행 의존성은 셋뿐입니다(react, react-dom, pretendard 글꼴) |
| 폐쇄망 | 외부 요청 0건. CDN, 외부 글꼴, 외부 API를 쓰지 않습니다 |
| 서버 붙이기 | 모든 상태 변경 함수가 `src/store.ts` 한 파일에 있습니다. 서버(DB)를 붙일 때 이 파일만 바꾸면 화면은 그대로 둡니다 |
| 데이터 구조 | 서버로 옮기면 표 다섯 개(단위업무, 반복업무, 담당, 회차 기록, 인계)가 중심입니다(`src/model.ts`) |
| 기관 자료 | 업무 기준표는 CSV 네 칸으로 주고받아, 기관의 기존 업무분장 표에서 바로 만듭니다 |
| 인수인계 문서 | 결정과 이유를 `docs/STRUCTURE.md`, AI 작업자용 안내를 `AGENTS.md`에 남겨 다음 개발자가 이어받습니다 |
| 보안 점검 | 공공 GitLab 보안 검사(Gitleaks, Semgrep, OSV-Scanner, Trivy, Syft)를 통과했습니다 |

## 자료와 보안

- 저장소의 사람, 부서, 업무, 기록은 모두 시연용으로 지어낸 것입니다. 실제 기관의 업무 기준표, 조직표, 개인정보는 넣지 않았습니다.
- `mock/전임자자료_김건강/`은 인수인계 시연에 쓰는 지어낸 전임자 자료(업무 메모, 지침, 일정표, 메일 정리)입니다.

## 폴더 구조

| 경로 | 내용 |
|---|---|
| `src/model.ts` | 데이터 모양과 시드 |
| `src/store.ts` | 모든 상태 변경(가입, 업무 맡기, 인수인계, 요청, 업무 표준, 발령) |
| `src/schedule.ts` | 반복 규칙 계산, 공휴일 |
| `src/parse.ts` | 한 줄 입력 해석(날짜, 시간, 반복) |
| `src/catalog.ts` | 업무 기준표 CSV 읽기·쓰기 |
| `src/views/` | 화면(오늘, 달력, 내 업무, 업무지식, 일정 등록, 업무 표준 등) |
| `src/data/` | 시연용 업무 기준표와 부서 목록 |
| `src/extract/` | 한글(HWPX)·워드·엑셀·텍스트 파일에서 글자를 뽑는 모듈(화면 연결 전) |
| `src/draft/` | 오핏 기록으로 인수인계 초안 항목을 만드는 규칙(화면 연결 전) |
| `scripts/screens/` | 시연 흐름 자동 점검 스크립트 |
| `docs/` | 설계와 결정 기록 |

## 지금의 한계

- 서버가 없어서 여러 사람이 같은 데이터를 함께 보지 못합니다. 시연은 한 브라우저에서 사람을 바꿔 가며 합니다.
- 전임자의 업무 폴더를 넣어 초안을 만드는 화면은 아직 없습니다.
- AI 모델 연결은 보류 중입니다.
- 실제 직원 대상 사용자 시험은 아직 하지 않았습니다.

# 오핏(OFIT)

[공공행정] 오핏(OFIT) — 반복 일정과 업무 노하우를 관리하고, 담당자가 바뀌어도 업무정보가 그대로 이어지는 웹서비스

2026 공공 AI 대전환 챌린지 세션 2 지정과제① 업무 바통(인수인계) 출품작입니다.

## 바로 써 보기

**https://950508lee-code.github.io/ofit-demo/** — 설치 없이 브라우저에서 열립니다(PC 권장). 자료는 그 브라우저에만 저장되고, 로그인 화면의 '처음 상태로 되돌리기'로 언제든 처음으로 돌아갑니다.

### 5분 체험 순서

시연 계정: **김건강**(광진지사, 예산·회계 담당) · **한경영**(경영지원 분류 관리자) · **최표준**(업무 표준 총괄 관리자). 사람은 왼쪽 아래 '시연용 계정 바꾸기'로 로그아웃 없이 바꿉니다.

| # | 해 볼 것 | 누를 곳 | 확인할 것 |
|---|---|---|---|
| 1 | 새 직원이 업무를 고른다 | 첫 화면 '새 직원으로 시작하기' → 이름 '박공단' → 부서 '광진지사' → 업무 '민원 응대' | 업무만 골랐는데 반복업무가 오늘·달력에 저절로 들어옵니다 |
| 2 | 할 일을 열어 본다 | 김건강으로 바꾸기 → '내 업무' → 예산·회계 '펼치기' → '지출결의 마감' | 오른쪽 판에 처리방법, **지난 처리 메모**(지난번에 남긴 한 줄), '완료'가 함께 보입니다. 오늘 화면의 할 일도 누르면 같은 판이 열립니다 |
| 3 | 처리방법을 고치고 되돌린다 | 같은 판의 '업무지식에서 보기' → 처리방법 '편집' → 한 단계 추가 → 저장 → '변경 기록' → 이전 판 '보기' → '이 판으로 복원' | 누구나 바로 고치고, 고친 기록이 남고, 잘못 고친 것은 되돌립니다 |
| 4 | 업무를 넘겨준다 | '내 업무' → 예산·회계 아래 '인수인계' → 박공단 고르기 → '보내기' | 넘길 업무와 앞으로 들어갈 일정이 미리 보입니다 |
| 5 | 업무를 넘겨받는다 | 박공단으로 바꾸기 → 오늘 맨 위 '받기' → '받은 업무' 판의 업무 이름 | 반복업무 목록·처리방법·참고자료·지난 기록·거쳐 간 사람이 그대로 넘어와 있습니다 |
| 6 | (선택) 업무 표준을 바꾼다 | '업무지식' → 예산·회계 → 반복업무 '+ 추가' → "매월 10일 예산 전용 신청 취합" → '보내기' → 한경영으로 바꿔 업무지식 맨 위에서 '승인' | 일정에 영향을 주는 변경만 관리자가 확인하고, 승인되면 같은 업무를 맡은 모두에게 들어갑니다 |

## 무엇을 해결하나

**문제.** 인사이동 때 쓰는 인수인계서에는 실제 일정, 처리 요령, 진행 상황 같은 업무 노하우가 충분히 담기지 않습니다. 자료는 개인 PC의 한글·엑셀·메일에 흩어져 있고, 떠나는 날 한꺼번에 기억을 되살려 쓰다 보니 빠지는 것이 생깁니다. 후임자는 과거 문서를 다시 찾고 주변에 물어 가며 처음부터 업무를 익힙니다.

**오핏의 방법 — 일의 주인은 사람이 아니라 업무(자리)입니다.**

- **업무를 고르면 일정이 들어옵니다.** 공공기관이 이미 쓰는 업무분장을 그대로 단위로 씁니다. 업무를 고르면 그 업무의 반복업무(예: 매월 25일 지출결의 마감)가 할 일과 달력에 들어오고, 주말·공휴일이면 앞 근무일로 당깁니다.
- **일하면서 남긴 것이 업무에 쌓입니다.** 처리방법, 주의할 점, 참고자료, 완료하며 남긴 한 줄이 사람이 아니라 업무에 붙습니다. 인수인계를 위한 입력을 따로 시키지 않습니다.
- **업무지식은 함께 쓰고, 기준은 확인을 거칩니다.** 처리방법·참고자료 같은 업무지식은 조직 구성원 누구나 바로 고치고(승인 없음), 고친 사람·시각·이전 판이 남아 비교하고 되돌릴 수 있습니다. 반복 주기처럼 모두의 일정을 바꾸는 업무 표준만 관리자가 확인합니다. 직원이 함께 쓴 처리방법은 공식 기준이 아님을 화면에 밝히고, 공식 근거(규정·지침)와 구분해 보입니다.
- **인수인계하면 업무와 기록이 통째로 넘어갑니다.** 받는 사람이 수락하면 반복업무·지난 기록·남긴 말이 그대로 옮겨 가고, 넘긴 사람의 지난 기록은 원래 자리에 남습니다. 발령(부서 이동)도 맡던 업무 정리 → 새 부서 → 받을 인수인계 → 업무 고르기를 한 흐름으로 합니다.
- **요청은 사람이 아니라 담당 업무로 갑니다.** 다른 부서에 보낸 요청은 '그 부서의 그 업무 담당자'에게 가고, 담당자가 바뀌면 새 담당자에게 갑니다.

**후임자가 다시 입력하지 않고 이어받는 것**

| 후임자에게 필요한 것 | 오핏에서 |
|---|---|
| 내가 맡은 업무 | 받은 인수인계나 업무 고르기로 정해집니다 |
| 오늘·이번 주에 할 일 | 맡은 날부터 반복업무 회차가 오늘 화면과 달력에 들어옵니다 |
| 어떻게 하는지, 주의할 점 | 반복업무마다 처리방법이 있고, 할 일을 열면 그 처리방법과 지난 처리 메모가 함께 보입니다 |
| 업무 전체의 흐름 | 업무지식에서 반복업무 목록을 보고, 반복업무 문서를 '이전 · 다음'으로 이어 읽습니다 |
| 진행 중인 일 | 업무 담당자 앞으로 온 요청은 새 담당자에게 옵니다. 개인 일정은 인수인계 때 골라 넘깁니다 |
| 참고자료 | 업무에 붙은 지침·서식의 위치와 시스템 주소가 그대로 있습니다 |

## 심사 기준별로 보기

### 활용성

| 심사 항목 | 오핏 |
|---|---|
| 행정업무 실정에 맞는 활용 | 업무분장(업무 → 반복업무)을 그대로 쓰고, 평소 하던 일(할 일 완료, 한 줄 기록, 처리방법 고치기)이 그대로 인수인계 자료가 됩니다 |
| 전 기관 공통 활용 | 특정 기관 전용 기능이 없습니다. 기관은 첫 화면 '우리 기관 등록하기'에서 업무 기준표(엑셀을 CSV로, 직렬·단위업무·반복업무·주기 네 칸, 빈 양식 제공)를 올려 시작합니다 |
| 기관별 설정 | 부서 구조, 분류(직렬)마다 업무 표준 관리자, 반복 주기(매일·매주 요일·매월 날짜/말일/n째 주 요일·분기·매년)를 기관이 정합니다 |
| 기대효과(정성) | 후임자는 첫날부터 할 일과 처리방법을 보고 일을 시작합니다. 전임자는 인수인계서를 처음부터 쓰지 않고, 쌓인 것을 확인하고 남길 말만 더합니다. 부서 사이 요청이 담당자 교체 때 끊기지 않습니다. 실제 직원 대상 효과 측정은 아직 하지 않았습니다 |

### 완성도

| 심사 항목 | 오핏 |
|---|---|
| 핵심 기능 | 가입·업무 고르기, 오늘·달력·빠른 입력("매주 금요일 3시 주간 회의"를 알아들음), 할 일 완료, 업무지식(업무 문서 · 반복업무 문서 · 처리방법 공동 편집 · 변경 기록·복원), 인수인계·발령, 부서 사이 요청(반복 포함), 업무 표준 제안·승인, 기관 등록(CSV), 알림이 모두 실제로 동작합니다 |
| 안정적 구동 | TypeScript strict로 작성했습니다. 자동 점검 스크립트가 헤드리스 크롬으로 시연 흐름 28단계, 공동 편집 9단계, 발령 장면 두 가지를 돌리며 단계마다 기대 결과를 확인합니다(앱 날짜를 고정해 요일과 상관없이 같은 결과). 외부 서버·외부 요청이 없어 네트워크 상태에 따라 멈추지 않습니다 |
| 사용 편의성 | 정부 디자인 시스템(KRDS) 기준(누르는 곳 44px 이상, 보조 글자 대비 4.5:1 이상)을 따릅니다. PC(1440px)가 기준이고 폰도 맞춰 씁니다. 단추 이름을 추가·편집·삭제·저장·취소처럼 한 가지 낱말로 통일하고, 처리방법처럼 일할 때 꼭 보는 정보는 접지 않고 바로 보입니다 |

### 확산 용이성

| 심사 항목 | 오핏 |
|---|---|
| 특정 모델에 묶이지 않는 구조 | 지금의 핵심 기능(업무 배정, 일정 계산, 입력 해석, 인수인계)은 AI 모델 없이 규칙으로 동작합니다. 모델이 없거나 바꾸는 기관에서도 그대로 씁니다. 전임자의 정리되지 않은 자료를 읽는 AI 기능은 OpenAI 호환 방식(`/v1/chat/completions`) 하나로 묶어 기관 안의 모델 주소와 이름만 바꾸게 설계했고, 모델이 낸 항목은 원문 인용을 프로그램이 대조한 뒤 전임자가 확인한 것만 넘깁니다(설계 완료, 구현 보류 — [`docs/SESSION2.md`](docs/SESSION2.md)) |
| 정보화사업 이관 | 서버 없는 정적 웹(Vite + React + TypeScript)입니다. `npm run build` 결과물을 웹 서버에 올리면 됩니다. 실행 의존성은 셋(react, react-dom, pretendard 글꼴), 외부 요청 0건이라 업무망(폐쇄망)에서 그대로 뜹니다 |
| 서버로 옮기기 | 모든 상태 변경이 `src/store.ts` 한 파일에 모여 있어, 서버(DB)를 붙일 때 이 파일만 바꾸고 화면은 그대로 둡니다. 데이터는 업무·반복업무·담당·회차 기록·인계 표가 중심입니다(`src/model.ts`) |
| 다음 개발자가 이어받기 | 확정된 구조와 결정 이유를 [`docs/STRUCTURE.md`](docs/STRUCTURE.md)에 날짜순으로 남겼습니다 |
| 보안 | 공공 GitLab 보안 검사(Gitleaks, Semgrep, OSV-Scanner, Trivy, Syft)를 통과했습니다 |

## 지금의 한계

- 서버가 없어 여러 사람이 같은 데이터를 함께 보지 못합니다. 시연은 한 브라우저에서 사람을 바꿔 가며 합니다.
- 전임자의 업무 폴더(한글·워드·엑셀)를 넣어 인수인계 초안을 만드는 기능은 글자 추출 모듈과 초안 규칙까지만 있고 화면은 없습니다. AI 모델 연결은 보류 중입니다.
- 반복 주기 변경·반복 중지는 명세만 확정했고 화면은 아직 없습니다. 참고자료는 아직 업무 단위로 붙습니다(반복업무별 연결은 다음 작업).
- 실제 직원 대상 사용자 시험은 아직 하지 않았습니다.

## 자료와 보안

- 저장소의 사람, 부서, 업무, 기록은 모두 시연용으로 지어낸 것입니다. 실제 기관의 업무 기준표, 조직표, 개인정보는 넣지 않았습니다.
- `mock/전임자자료_김건강/`은 인수인계 시연에 쓰는 지어낸 전임자 자료입니다.

## 기관에서 설치해 쓰기

Node.js 20.19 이상(또는 22.12 이상)이 필요합니다.

```
npm install
npm run build      # dist/ 폴더의 정적 파일을 기관 웹 서버에 올립니다
```

개발·점검용으로 띄울 때는 `npm run dev`(http://localhost:5180)를 씁니다. 자동 점검 방법과 전체 시연 순서는 [`docs/DEMO.md`](docs/DEMO.md)에 있습니다.
